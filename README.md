# PBIX -> Dataflow -> Physical Source Lineage Tool

Traces every table in a Power BI report (.pbix) back through its Power Query
dataflow dependencies to the final physical source (Oracle schema/table,
SharePoint/Excel file, CSV, Web URL), and produces an Excel workbook report.

## Requirements

- Python **3.12** (pbixray does not ship wheels for 3.14+; this must be the
  interpreter used to create the venv below).
- Windows PowerShell.

## Setup on a new machine

```powershell
powershell -ExecutionPolicy Bypass -File setup.ps1
.venv\Scripts\Activate.ps1
```

This creates a `.venv` folder and installs the exact pinned dependency
versions from `requirements.txt` (`pbixray`, `openpyxl`, `pandas`, `numpy`).

If `python` on PATH is not 3.12, edit the `$pythonExe` line at the top of
`setup.ps1` to point at your 3.12 interpreter (e.g.
`C:\Python312\python.exe`), or run the two commands manually:

```powershell
C:\Path\To\Python312\python.exe -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
```

## Pointing the tool at your own files

Edit **`config.py`** — it's the single place every script reads its input/
output paths from:

```python
PBIX_PATH = _p("DTS - CashPlus-Dashboard (1).pbix")   # your .pbix file
DATAFLOW_FOLDER = _p("PowerBIDataflows")               # folder of exported dataflow JSON files
TARGET_XLSX = _p("CASHPLUS-DASHBOARD 1.xlsx")          # existing/reference lineage workbook to compare against
```

Paths are resolved relative to the project folder by default (via `_p(...)`)
so the whole folder can be copied/cloned anywhere without further edits, as
long as the files keep the same names. To use files that live elsewhere,
just replace `_p("...")` with an absolute path string for that entry.

## Running the pipeline

```powershell
.venv\Scripts\Activate.ps1
python build_lineage_report.py
```

This single command produces **both** output workbooks:

- `Generated_CashPlus_Lineage.xlsx` — the main report (CashPlus-style layout:
  used/unused tables, Level 1/Level 2 dataflow columns, dataflow file
  coverage).
- `Dataflow_Table_Lineage_Report.xlsx` — a companion report in a simpler
  "Overview" + "Table Lineage" layout (one row per table, with a
  human-readable narrative "Lineage Path" column), generated by
  `build_dataflow_table_lineage_report.py` and reusing the exact same
  `lineage_lib.py` engine, so both reports always stay consistent.

Both are **self-contained / authoritative by default** — there's no
requirement to have a target/reference workbook to validate against. Every
row the engine can't resolve with full confidence is flagged
`NEEDS MANUAL OVERRIDE` (highlighted yellow) with a specific issue-type tag
in the Remarks / "Unresolved Reason" column, e.g.:

- `DATAFLOW NOT FOUND` — the M-code references a dataflow not among the
  provided JSON files.
- `NO CONNECTOR ANCESTOR` — no local query in the dependency chain calls a
  dataflow/physical connector at all.
- `UNRESOLVABLE GUID / REFERENCE ENTITY` — a linked entity's GUID couldn't
  be resolved to a dataflow name (see `guid_dataflow_names.json` below).
- `AMBIGUOUS ENTITY MATCH` — the entity name matched more than one provided
  dataflow file; the engine picked one by name similarity, but it should be
  confirmed.
- `MISSING SCHEMA` — an Oracle-backed table whose source dataflow never
  states a schema in its own M-code.
- `MULTI-SOURCE UNION` / `MULTI-SOURCE UNION (DATAFLOW LEVEL)` /
  `UNION WITH LOCAL PATCH TABLE` — a `Table.Combine` union with more than
  one real source; the union members are listed for manual review.

QA for a new PBIX file (no target workbook needed) = run the pipeline, then
scan for yellow/`NEEDS MANUAL OVERRIDE` rows and resolve each one manually.

### Optional: comparing against a reference workbook

If a target/reference workbook does exist for a report (as it does for the
current CashPlus project), you can still validate against it:

```powershell
python compare_final_source_table.py  # compares Generated_CashPlus_Lineage.xlsx against config.TARGET_XLSX
```

This is optional/legacy — it is **not** part of the default workflow for
future PBIX files that don't have a reference workbook.

## Manual-override data files (travel with the repo, not machine-specific)

- `guid_dataflow_names.json` — resolves cross-workspace dataflow references
  that only carry a GUID (no readable name) in the M-code; add entries here
  when a report references a dataflow you can identify by its
  `https://app.powerbi.com/groups/{workspaceId}/dataflows/{dataflowId}` URL.
- Every other kind of low-confidence result (missing schema, ambiguous
  match, multi-source unions, unresolved references) is flagged inline in
  both reports as `NEEDS MANUAL OVERRIDE` — there is no separate override
  file for these; resolve them directly in the generated workbook.

## Project files

| File | Purpose |
|---|---|
| `config.py` | All machine/project-specific input & output paths |
| `lineage_lib.py` | Core M-code parsing / multi-level resolution engine |
| `build_lineage_report.py` | Runs the pipeline end-to-end; writes `Generated_CashPlus_Lineage.xlsx` and (via `build_dataflow_table_lineage_report.py`) `Dataflow_Table_Lineage_Report.xlsx` |
| `build_dataflow_table_lineage_report.py` | Writes the companion `Dataflow_Table_Lineage_Report.xlsx` (Overview + Table Lineage sheets); can also be run standalone |
| `compare_final_source_table.py` | Optional/legacy: compares the generated report against a target/reference workbook |
| `validate_report.py` | Older validation script (superseded by `compare_final_source_table.py`) |
| `requirements.txt` | Pinned dependency versions |
| `setup.ps1` | One-command environment setup |
